**⚠️ 协商** = 改之前先在提交说明里写清楚，避免和对方撞。

| 路径 | 归属 |
| --- | --- |

| `renderer/index.html` | 🔒 |
| `renderer/core/**` | 🔒 |

>
> **如果你是被重新拉来并行开发的第二个智能体，这条豁免不适用**，仍按第 6 节走申请流程。
>
> 顺带把外壳层现在**已经定下来的交互语义**记在这里，免得模式层的人假设错：

## 3. 模式模块接口

每个模式就是一个文件，导出一个对象挂到 `window.Naiwa.Modes.<id>` 上。核心层（`app.js`）会按当前模式查表分发事件。

### 3.1 骨架

```js
// renderer/modes/relax.js
'use strict';
(function () {
  window.Naiwa = window.Naiwa || {};
  window.Naiwa.Modes = window.Naiwa.Modes || {};

  let ctx = null;              // 核心层注入的服务句柄

  window.Naiwa.Modes.relax = {
    id: 'relax',
    label: '解压模式',

    // ──────── 生命周期 ────────

    /** 切换到本模式时调用。加载素材、建定时器、初始化状态。 */
    async activate(c) {
      ctx = c;
      await ctx.pet.preload(['laugh', 'run']);   // 预热，保证后续能同步启动
    },

    /** 离开本模式时调用。**必须**清掉所有定时器、临时 DOM、进行中的表演。 */
    deactivate() {
      clearTimeout(/* ... */);
    },

    // ──────── 事件（全部可选，不实现就不分发） ────────

    /** 左键点击奶蛙。注意：拖拽已在核心层过滤掉，这里收到的都是纯点击。 */
    onClick(ctx) {},

    /** 鼠标在窗口内移动。x / y 是窗口内客户端坐标，与 mousemove 事件一致。 */
    onPointerMove(ctx, x, y) {},

    /** CPU 占用变化，约每 2 秒一次。0~100。 */
    onCpu(ctx, percent) {},

    /** 空闲心跳，每 5 秒一次。idleMs = 距上次交互的毫秒数。 */
    onIdleTick(ctx, idleMs) {},

    /** 面板开合变化。只有工作模式会用到。 */
    onPanelToggled(ctx, isOpen) {},

    // ──────── 元信息 ────────

    /** 本模式用到的素材槽位名，供自检工具核对。 */
    assetSlots: ['idle_relax', 'laugh', 'run'],
  };
})();
```

### 3.2 调用约定

- **所有方法都可能不被调用**，不要依赖调用顺序。
- `activate` 是异步的，核心层会 await。里面可以放心做素材加载。
- `deactivate` **必须是同步的且必须清理干净**。用户可能疯狂右键来回切模式，残留的定时器会让两个模式的行为叠在一起。
- 事件回调里**不要抛异常**，核心层虽然做了 try/catch，但异常会打断该次事件的其他处理。

## 4. `ctx` 服务清单

核心层注入的 `ctx` 是你唯一能碰到共享能力的入口。**不要绕过它直接操作 DOM 或 window。**

### 4.1 `ctx.pet` — 表现层

```js
// 切回本模式的静态待机图（两个模式的待机都不做动作，就是一张静态图）
await ctx.pet.setIdle();

// 播一次性反应。返回预计总时长（ms），播完自动回静态待机。
// opts: { duration, hold, onEnd }
const ms = await ctx.pet.playOnce('laugh', { duration: 1600 });

// 播循环状态（跑步这种）。需要自己调 stopLoop() 结束。
await ctx.pet.playLoop('run');

// 停止循环状态，回静态待机
ctx.pet.stopLoop();

// 某槽位有没有「真正可用」的素材（false = 会退回占位奶蛙）。
// ⚠️ **异步的**：它要确认素材真的挂载成功，而不只是清单里声明了。
// 路径写错时只看声明会把画风完全不同的占位卡通蛙当真素材挂上去。
// 查叠加层要传第二个参数：await ctx.pet.has('sweat', 'overlay')
const hasRun = await ctx.pet.has('run');   // → boolean

// 是否正在做一次性反应
ctx.pet.isReacting();          // → boolean

// 叠加特效开关。**当前两个模式都没用到**（打盹已取消，流汗改成了换基础图），
// 但核心能力保留着，将来想加透明叠加层随时可以用。
await ctx.pet.setOverlay('sweat', true);

// 台词气泡
ctx.pet.say('哈哈哈哈！', 1500);

// 判断某个窗口内坐标是否落在奶蛙身上（椭圆判定，已自动考虑跑步产生的位移）
ctx.pet.containsPoint(x, y);   // → boolean

// 视线跟随（内置占位素材支持；真实素材的视线是画在图里的）
ctx.pet.lookAt(x, y);          // 传客户端坐标即可，内部会归一化

// 预加载动画。**同步播放前必须先调这个**，否则首次播放会有加载延迟导致不同步。
await ctx.pet.preload(['laugh', 'run', 'sweat']);

// 分身同步表演 —— 解压模式连点专用
const ms = await ctx.pet.performWithClones('laugh', {
  clones: 2,       // 分身数量，默认 2
  spread: 0.85,    // 分身横向展开距离，相对主体宽度，默认 0.85
  scale: 0.82,     // 分身缩放，默认 0.82
  opacity: 0.92,   // 分身不透明度，默认 0.92
  fadeOut: 160,    // 消失淡出时长（ms），默认 160
  onEnd: () => {}, // 表演结束回调
});
```

### 4.2 `ctx.audio`

```js
// 播放音效，返回时长（ms）。音频文件缺失时自动退回内置合成音效。
const ms = ctx.audio.play('laugh');

// 合成音效可用的名字：
// laugh / laugh_hard / bubble / pop / chime / drip / done
```

### 4.3 `ctx.panel` — 只有工作模式用

```js
await ctx.panel.open();        // 打开（可传 'notes' / 'clips' 指定标签页）
ctx.panel.close();
ctx.panel.toggle();
ctx.panel.isOpen();            // → boolean
await ctx.panel.refresh();     // 重新拉取数据
```

### 4.4 其他

```js
ctx.toast('已复制', 1600);     // 底部提示条
ctx.log('切到跑步状态');        // 带 [relax] / [work] 前缀的日志
```

## 5. 工作流：串行开发

**当前方案：先把解压模式做完，再开始工作模式。** 不是并行。

串行消除了**并发冲突**，但换来了两个新风险。这一节就是讲怎么防住它们。

### 5.1 串行 ≠ 没有风险

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| ~~并发冲突~~ | 两人同时改同一个文件 | ✅ 串行已消除 |
| **回归风险** | 后做的人改坏了先做的人的东西 | 🅱 不许动 🅰 的文件和共享层；🅱 开工前先跑一遍 🅰 的功能当基线 |
| **结构债** | 先做的人把逻辑堆进 `app.js`，后做的人只能在别人的代码里找地方塞 | 🅰 **必须先把结构拆好**，见 5.2 阶段 1 |

**所以第 2 节的「文件所有权」表继续有效**——只是作用从「防并发冲突」变成了「防回归」。

这也是串行最容易吃亏的地方：没有冲突了，人就会松掉边界意识，然后 B 顺手"改进"了 A 的代码，把一个好好的功能改坏。

### 5.2 阶段划分

| 阶段 | 负责 | 目标 | 交付 |
| --- | --- | --- | --- |
| **阶段 1 · 结构改造** | 🅰 | 单体代码 → 分层结构 | 见 5.3 结构部分 |
| **阶段 2 · 解压模式** | 🅰 | 功能可用 | 点击大笑 / 连点分身 / 久闲置跑步 |
| **阶段 3 · 工作模式** | 🅱 | 功能可用 | 面板 / 便签 / 剪贴板 / CPU / 打盹 |

**阶段 1 是 🅰 的任务，不是「有空再说」的前置条件。** 详细清单见 [`01-解压模式.md`](01-解压模式.md) 第 2 节。

> **为什么让 🅰 做，而不是单独找人做？**
> 因为 🅰 本来就要改 `pet.js`（跑步要 `playLoop`、分身要 `performWithClones`），已经会动共享层了，
> 把结构改造一起做掉最省事，也少一次交接。
>
> **但必须当成一个独立阶段做完并验收**，不要当写功能时顺手做的事——
> 顺手做出来的结构，通常经不起后面的人用。

### 5.3 🅰 → 🅱 交接清单

**🅰 完成时必须满足以下全部条件，🅱 才能开工。** 这份清单同时也是 🅰 的最终验收标准。

**结构**

- [ ] `renderer/core/` 建好（`style.css` / `assets.js` / `audio.js` / `pet.js`）
- [ ] `app.js` **只做路由和事件分发**，不再内联任何模式逻辑
- [ ] `assets/manifest.js` 只保留共享部分（`canvas` / `hit` / 静态待机图），并合并下面两个
- [ ] `assets/manifest.relax.js`、`assets/manifest.work.js` 建好
- [ ] `renderer/modes/relax.css`、`work.css` 建好
- [ ] `renderer/modes/work.js` 有**完整方法签名的空壳**，🅱 直接往里填
- [ ] `__verify.js` 能校验拆分后的三个 manifest

**能力**

- [ ] `ctx` 按第 4 节的规格完整实现
- [ ] `pet.js` 的 `playLoop` / `stopLoop` / `preload` / `performWithClones` 可用
- [ ] 跑步位移加在 `#pet` **本身**，命中判定能跟着走

**功能**

- [ ] 解压模式全部功能可用（见 01 文档第 8 节验收清单）
- [ ] **切到工作模式不报错**——虽然是空壳，但应用不能崩
- [ ] 删掉所有素材仍能启动，退回占位奶蛙
- [ ] `npm run check` 通过

**文档**

- [ ] 写一份 `docs/交接-A到B.md`，说清楚：
  - 改了哪些**冻结层**文件、为什么改
  - `ctx` 有没有和这份文档不一致的地方（**有就必须写下来**）
  - 留给 🅱 的注意事项和已知问题

### 5.4 🅱 开工前要做的

1. 读 `docs/交接-A到B.md`
2. **跑一遍解压模式，确认 🅰 的功能正常**——这是你的基线。之后任何时候发现解压模式坏了，就知道是自己改的
3. 确认自己只动第 2 节里标 🅱 的文件
4. 如果发现 🅰 留下的结构有问题，**不要默默绕过**——写进 `docs/交接-A到B.md` 或在提交说明里写清楚

### 5.5 关于并行

如果以后要改回并行（比如两个模式都需要大改），只要 🅰 按 5.2 完成了阶段 1，阶段 2 和 3 就能同时开工——因为文件边界已经划清了。

也就是说：**阶段 1 只投入一次，之后想并行想串行都行。** 这一步的价值不因为串行而减少。

## 6. 需要冻结层新增能力时怎么办

如果你发现需要的新能力不在 `ctx` 里（比如解压模式想加"奶蛙跟随鼠标跑动"，或者工作模式想加"全局快捷键"）：

1. **不要直接改冻结文件。**
2. 不要自己写 `require('electron')` 或直接操作 `main.js` 的 IPC。
3. 正确做法：在你的任务文档里追加一节「**申请的共享层能力**」，写清楚：
   - 需要什么能力
   - 为什么模式层自己实现不了
   - 期望的接口签名
4. 由主控智能体统一加到共享层，再通知你接口就绪。

**理由**：共享层是两个人的公共地基。任何一个人私自改，都会让另一个人的代码在不知情的情况下行为改变——这类 bug 极难排查。

## 7. 文件边界纪律

| 规则 | 原因 |
| --- | --- |
| 只改「你的」文件 | 越界是所有协作失败的头号原因 |
| 不新建 `renderer/` 根目录下的文件 | 会打乱 `index.html` 的加载顺序 |
| 模式专属的 CSS 写进 `modes/<你的模式>.css` | 别往 `core/style.css` 里加 |
| 模式专属的素材声明写进 `manifest.<你的模式>.js` | 别往 `manifest.js` 里加 |
| 想加共享依赖（npm 包）先说 | 会改 `package.json`，串行下也要让另一方知道 |
| 提交信息写清模式名 | 例：`[relax] 实现连点分身同步大笑` |

### ⚠️ 串行开发特有的两条

**这两条是并行时不需要、串行时必须的：**

| 规则 | 原因 |
| --- | --- |
| **🅱 不许"顺手改进"🅰 的代码** | 并行时越界会立刻冲突暴露；串行时越界会静默改坏一个已经验收过的功能，而且没人发现 |
| **改了冻结层就必须写进交接文档** | 接手的人只会读 `00-协作约定.md`。没写下来的改动，对他就是"文档和代码不一致" |

**为什么串行反而更危险**：没有冲突报警了，人会松掉边界意识。"这个函数写得不好我重构一下"——重构完解压模式坏了，而 🅱 根本不知道是自己弄的。

**关于 `assets/shared/`：** 静态待机图放这里。如果需要新增共享素材，先确认另一方不需要同名文件，再放进去。

## 8. 素材怎么交付

**结论：直接复制到工作区，不要在对话里发图。**

原因（每一条都会真实咬人）：

1. **对话传图会被重新编码，PNG 的透明通道极可能丢失。** 一旦被转成 JPEG，白底就焊死在图上了——而透明通道是这个项目的**命根子**，没有它桌面上就是一块白板。
2. 传图通常还会压缩降质，边缘出现噪点，抠图白做。
3. 落不到正确的路径和文件名，`manifest` 里写的路径对不上，加载必然失败。
4. `npm run check` 没法校验，只能等运行时才发现问题。

### 交付方式

把文件**直接放进对应目录，按约定命名**：

```
naiwa-pet/assets/
├── shared/
│   ├── idle_relax.png       解压模式静态待机（必需）
│   └── idle_work.png        工作模式静态待机（可选，缺省复用 idle_relax）
├── relax/                   ← 解压模式智能体负责
│   ├── laugh/               大笑序列帧 → laugh_0001.png, laugh_0002.png ...
│   ├── laugh.webm           或：带 alpha 的 WebM
│   ├── run/                 跑步序列帧 → run_0001.png ...
│   └── run.webp             或：动画 WebP
├── work/                    ← 工作模式智能体负责
│   ├── sweat.webp           流汗叠加层（只画汗滴，背景透明）
│   └── zzz.webp             打盹叠加层（只画 Z 字，背景透明）
└── sfx/
    ├── laugh.mp3
    ├── run.mp3
    └── ...
```

### 格式硬性要求

| 用途 | 推荐 | 禁止 |
| --- | --- | --- |
| **单次播放**（大笑） | **PNG 序列帧** 或 WebM (VP9+alpha) | ❌ GIF / 动画 WebP（无法可靠重播，会闪） |
| **循环播放**（跑步、流汗、打盹） | 动画 WebP / GIF / 序列帧 | ❌ MP4（无透明通道） |
| **静态待机** | 单张 PNG（透明背景） | ❌ JPEG |
| **叠加特效** | 只画特效本身，其余区域全透明 | ❌ 完整的流汗奶蛙（会把待机图整个盖住） |

**⚠️ 关于「分身同步大笑」的特别要求：**

大笑动画**强烈建议用 PNG 序列帧，不要用视频**。

原因：连点触发时，主体和 2 个分身必须**在同一帧启动**。三个独立的 `<video>` 元素各自解码，误差可能有几十毫秒，看起来就是"不齐"。序列帧由同一个帧计数器驱动，可以做到严格同帧。

素材要求：

- 显示区 190×190 CSS px，素材建议 **380×380**（2 倍图，应对 Windows 125%~150% 缩放）
- 大笑时长 1.2~2 秒，跑步循环 0.6~1.2 秒
- 单文件体积：循环动画 < 500KB，单次动画 < 800KB，特效 < 150KB

详细的转换命令（ffmpeg）见项目根目录的 [`ASSETS.md`](../ASSETS.md)。

## 9. 通用验收流程

两个模式都适用：

```bash
cd naiwa-pet
npm install          # 首次
npm start            # 启动
npm run check        # 自检：验证素材声明，抓常见错误
```

### 必须通过的检查

1. **`npm run check` 无错误。** 提醒（`!`）可以留，但要知道为什么。
2. **素材缺失时程序仍能启动。** 每个槽位都退回内置占位奶蛙，不能白屏或崩溃。
3. **切模式来回 20 次不出问题。** 验证 `deactivate()` 清理干净了。
4. **点击穿透正常。** 鼠标移到奶蛙身上能点，移到旁边透明区域能点到桌面图标。
5. **`Ctrl + R` 重载后状态一致。**

- [ ] 我只改了自己名下的文件？

- [ ] 素材缺失时会退化还是会崩？
- [ ] 连续快速操作（狂点、疯狂切模式）会不会出问题？

## 10. 两种模式的共同底线

无论哪个模式，这几条不能破：

1. **不联网。** 所有数据本地存储。剪贴板和便签都是用户的隐私数据。
2. **不阻塞主线程。** 任何超过 16ms 的同步操作都要挪走或分片。
3. **不残留。** 模式切走后，不能还有属于它的定时器在跑、DOM 在闪。
4. **不崩。** 素材缺失、数据损坏、IPC 失败，都要能降级运行。
5. **对用户内容一律用 `textContent`，绝不用 `innerHTML`。** 剪贴板里可能夹带 `<script>`，用 `innerHTML` 就是自己开 XSS 口子。
