## 1. 一句话目标

一只安静的桌面助手：点它弹出一个面板，里面能记便签待办、能翻剪贴板历史；电脑忙起来它会整只换成一张「累瘫」的图。

**待机状态不做任何动作**——就是一张静态图，安静地待在角落，不抢注意力。

## 开工前必做的四件事

### ① 读交接文档

```bash
cat docs/交接-A到B.md
```

这是上一个智能体留下的。里面会写清楚：它改了哪些冻结层文件、`ctx` 有没有和 `00-协作约定.md` 不一致的地方、有哪些已知问题。

**如果 `ctx` 和约定文档不一致，以交接文档为准**，并且要反馈回去。

### ② 跑一遍解压模式，建立基线 ⭐

```bash
npm install
npm start
```

**把解压模式的功能全部试一遍**（点击大笑、连点出分身、闲置跑步），确认它们是正常的。

这一步的意义：这是你的**基线**。之后任何时候发现解压模式坏了，你就能确定是自己改的，而不用怀疑是不是接手时就是坏的。

**跳过这一步，后面出了回归问题你会花大量时间在"到底是谁弄坏的"上。**

### ③ 确认文件边界

你**只**能动第 2 节里标 🅱 的文件。特别是：

- ❌ 不要动 `renderer/core/**` —— 那是共享层，解压模式正在用它
- ❌ 不要动 `renderer/modes/relax.js` / `relax.css`
- ❌ 不要动 `assets/relax/**`
- ❌ 不要"顺手改进"解压模式的代码

### ④ 发现结构问题怎么办

如果上一个智能体留下的结构有问题（比如 `ctx` 少了个你需要的能力、`app.js` 的路由有 bug）：

**不要默默绕过，也不要直接改。**

1. 能在自己文件里绕过的 → 绕过，但**写进 `docs/交接-A到B.md` 或提交说明里**
2. 绕不过的 → 走约定文档第 6 节的申请流程

理由：共享层是两个人的地基。你私自改，解压模式会在你不知情的情况下行为改变——这类 bug 极难排查。

## 4. 行为规格

### 4.1 静态待机

一张静态图，什么都不做。**不要加呼吸、摇摆、敲键盘之类的循环动画**——这是明确需求。

工作模式的待机图应该传达"安静"：姿势收敛、不占视觉重心。用户正在专注做事，桌宠不该在旁边动来动去。

允许保留：视线跟随（`ctx.pet.lookAt`），以及 `sweat` / `zzz` 两个叠加特效。

### 4.2 点击 → 开合面板

```
点击奶蛙
  ├ 面板已开 → 收起（播 pop 音效）
  └ 面板已关 → 展开（播 bubble 音效）
```

**首次展开时**建议给个引导，比如气泡提示"记点什么吧"，或者直接聚焦到输入框（现在的代码是自动 focus 输入框）。

### 4.3 便签 / 待办

**已有基础代码（`panels.js`），需要你完善到能用。**

| 功能 | 要求 |
| --- | --- |
| 新增 | 输入框 + 添加按钮，`Ctrl + Enter` 快捷保存 |
| 勾选完成 | 打勾 + 删除线 + 播放 `done` 音效 + **奶蛙笑一下**（复用 `laugh` 动画，零额外素材成本，是很好的正反馈） |
| 删除 | 悬停显示删除按钮 |
| 编辑 | 双击文字进入编辑态（**当前代码没实现，需要补**） |
| 排序 | 未完成在前，已完成沉底；同组内按创建时间倒序 |
| 空状态 | 显示引导文案而不是空白 |

**完成反馈的细节**：勾选完成时触发奶蛙笑一下，是让"待办"这件事和"桌宠"产生联系的关键。没有这个，它只是个普通记事本。

### 4.4 剪贴板历史

**已有基础代码，需要你完善。**

| 功能 | 要求 |
| --- | --- |
| 自动记录 | 由 `main.js` 每 700ms 轮询，已实现，你只管展示 |
| 去重 | 已实现：重复内容只移到最前，不新增 |
| 点击复制 | 点条目直接复制回剪贴板，播放 `pop`，冒提示"已复制" |
| 置顶 | ★ 按钮。**置顶项在「清空」时会保留** |
| 删除单条 | ✕ 按钮 |
| 清空 | 只清未置顶的 |
| 搜索 | 对文本内容做子串匹配（**当前是简单 includes，够用；数据量大再考虑加索引**） |
| 显示元信息 | 相对时间（"3 分钟前"）+ 内容大小 |
| 超长内容 | 最多显示 3 行，超出省略 |
| 上限 | 200 条，超出丢弃未置顶的旧记录（已在 `main.js` 实现） |

**实时刷新**：面板开着且停在剪贴板页时，收到 `onClipsUpdated` 推送要立即重绘。停在便签页时不用重绘，省开销。

### 4.5 CPU 高 → 换成流汗状态图

**触发逻辑（滞回，很重要）：**

```
CPU ≥ 75%   →  整只换成 sweat 状态图（播 drip 音效 + 冒一句「电脑好烫…」）
CPU ≤ 62%   →  换回静态待机图
```

**必须留滞后区间。** 只用单一阈值（比如 75%）的话，负载在阈值附近波动时奶蛙会疯狂来回切换，看起来像 bug。75 开 / 62 关是起点，可以调。

**怎么切：**

```js
// CPU 飙高
await ctx.pet.playLoop('sweat');     // 整只换成流汗状态图
ctx.audio.play('drip');
ctx.pet.say(CONFIG.HEAT_LINE, 2000);

// CPU 降下来
ctx.pet.stopLoop();                  // 换回本模式的静态待机
```

> `playLoop` 这名字听起来像「播循环动画」，但它真正的语义是「**进入一个持续状态**」——
> 循环动画可以，静态姿势也可以，两者都由 `stopLoop()` 结束。流汗用的就是后者。

**其他要求：**

- CPU 值已经在 `ctx.onCpu(percent)` 回调里给你了，约 2 秒一次
- 面板底部那个 CPU 徽标**由核心层 `app.js` 调 `Naiwa.Panels.setCpu()` 更新，你不用管**
- 换的是**基础图**不是叠加层——所以不是待机图上「多出一层汗」，而是整只奶蛙换成另一张
- `deactivate()` 里必须 `ctx.pet.stopLoop()`，否则切到解压模式后还挂着流汗状态图
- **素材没就位时的降级**：`await ctx.pet.has('sweat')` 返回 `false` 时**不要**调 `playLoop('sweat')`——那会挂上画风差很远的占位卡通蛙。退化成「只播 drip 音效 + 冒一句台词」即可

> ⚠️ **`ctx.pet.has()` 是异步的，必须 `await`。** 它要确认素材**真的挂载成功**，
> 而不是只看清单里声明了没有：路径写错时只看声明会把占位卡通蛙当真素材挂上去。
> 详见 [`docs/00-协作约定.md`](00-协作约定.md) 第 4.1 节。

### 4.6 久不操作 → 打盹

**已取消。** 这个功能不做，`onIdleTick` 可以完全不实现（或者留着空实现）。

理由：拿不到打盹素材，而且工作模式下奶蛙本来就该安静，少一个状态少一份干扰。

核心层的 `ctx.pet.setOverlay()` 还在，将来想加回来随时可以用。

## 5. 关键技术点

### 5.1 隐私（这个模式最需要认真对待的地方）

剪贴板历史记录的是**用户复制过的一切**——密码、身份证号、私聊内容、公司文档片段。这个功能做不好会造成真实伤害。

**必须做到的：**

| 要求 | 说明 |
| --- | --- |
| **纯本地** | 不联网、不上传、不埋点。任何"改进体验"的网络请求都不要加 |
| **明文存储要告知** | 数据目录里是明文 JSON。UI 上要有"仅存本地"的说明，别让用户以为加密了 |
| **一键关闭** | 托盘菜单已有「记录剪贴板历史」开关。**面板里也要有一个**，让用户在当前上下文就能关掉 |
| **一键清空** | 面板里的「清空」按钮要显著，且清空后不可恢复（要提示） |
| **不主动读敏感格式** | 只读文本。**不要去读图片、文件路径、自定义格式**——那会大幅扩大暴露面 |
| **自己写回的不重复记录** | `main.js` 已处理（复制历史条目时不会又记一条） |

**不要做的事：**

- ❌ 不要尝试"智能过滤密码"——启发式规则会漏，还会误删用户的正常内容，反而制造"为什么这条没记上"的困惑。给开关比给过滤器诚实。
- ❌ 不要把剪贴板内容写进日志。
- ❌ 不要在内容预览里渲染富文本或 HTML。

**XSS 提醒**：剪贴板里可能夹带 `<script>alert(1)</script>` 这类内容。所有用户内容**一律用 `textContent` 写入，绝不用 `innerHTML`**。现有 `panels.js` 已经这么做了，你继续遵守。

### 5.2 面板与点击穿透

核心层用「鼠标是否落在 `#panel` 内」+「是否落在奶蛙命中椭圆内」来决定窗口要不要接收鼠标事件。

**你要保证的两件事：**

1. **面板隐藏时必须是真的 `display: none`**（现有代码用 `hidden` 属性 + CSS，是对的）。如果只是 `opacity: 0` 或 `visibility: hidden`，`elementFromPoint` 仍可能命中它，导致窗口在看不见的地方拦截鼠标，用户点不到桌面图标。
2. **不要让任何元素超出面板边界**（比如弹出的浮层、tooltip 跑到面板外面）。超出部分不在命中判定范围内，用户点它会穿透到桌面，体验很怪。

如果确实需要浮层，用 `ctx` 申请扩展命中区域。

### 5.3 数据持久化与损坏恢复

数据由 `main.js` 写到 `%APPDATA%\naiwa-pet\naiwa-data.json`，写入做了 400ms 防抖。

**你需要处理的情况：**

| 情况 | 期望行为 |
| --- | --- |
| 文件不存在（首次运行） | 用空数组，正常启动 |
| JSON 解析失败（写一半断电） | `main.js` 已 catch 并回退默认值。**但要在 UI 上提示用户数据可能丢了**，而不是静默变成空白 |
| 单条数据缺字段（`text` 是 undefined） | 渲染时跳过，不要让整个列表崩掉 |
| 数据量很大（1000+ 条便签） | 列表要能滚动，不要一次性渲染几千个 DOM 节点 |

**建议**：便签超过 200 条时提示用户归档，或者做虚拟滚动。

### 5.4 CPU 采样够不够用

`main.js` 用 `os.cpus()` 的累计时间差算全局 CPU 占用，2 秒采样一次。

- **够用**：判断"电脑忙不忙"这个粒度完全足够。
- **不够用**：如果你想要更细的（比如分核心、内存、磁盘），需要走申请流程，让主控智能体在 `main.js` 里加（可能要引入 `sysinfo` 之类的依赖）。

**不要自己在渲染进程里轮询系统状态**——渲染进程没有 Node 能力，而且会额外增加窗口进程的负担。

## 6. 状态机

```
        ┌───────────────────────────────┐
        │          静态待机              │
        │      （一张图，不做动作）       │
        └───┬───────────────────────┬───┘
            │                       │
        点击 │                   CPU≥75%
            ▼                       ▼
      ┌──────────┐           ┌──────────────┐
      │ 面板展开  │           │ 流汗状态图    │
      │          │           │（换基础图）   │
      └────┬─────┘           └──────┬───────┘
           │                        │
       再点击 │                   CPU≤62%
           ▼                        ▼
        （收起）                （换回待机）
```

**面板与状态图互相独立**：面板开着的时候 CPU 飙高，照样应该换图。两者不冲突。

**没有打盹状态了**——原方案里的 `zzz` 已取消。

## 7. 可调参数

在 `renderer/modes/work.js` 顶部放一个 `CONFIG` 对象：

```js
const CONFIG = {
  // CPU 流汗（滞回阈值，必须留滞后区间）
  CPU_ON: 75,             // ≥ 这个值换成流汗状态图

  // 面板
  CLIP_PREVIEW_LINES: 3,    // 剪贴板条目最多显示几行
  NOTES_VIRTUALIZE_AT: 200, // 便签超过多少条时启用虚拟滚动

  // 台词
  HEAT_LINE: '电脑好烫…',
};
```

## 8. 验收清单

功能层面：

- [ ] 进入模式后奶蛙是**静止**的，没有任何循环动画
- [ ] 点击奶蛙 → 面板展开 + `bubble` 音效；再点 → 收起 + `pop` 音效
- [ ] 便签能新增（含 `Ctrl + Enter`）、勾选、删除、编辑
- [ ] 勾选完成 → 打勾 + `done` 音效 + 奶蛙笑一下
- [ ] 剪贴板能自动记录、去重、点击复制、置顶、删除、清空、搜索
- [ ] 置顶项在「清空」后被保留
- [ ] CPU 拉高（开个烤机软件或跑个编译）→ **整只奶蛙换成流汗状态图**
- [ ] CPU 降下来 → **换回待机图**，且**阈值附近不会反复来回切**
- [ ] **没有打盹功能**（原方案已取消，不该看到 Z 字）
- [ ] 面板开着时 CPU 飙高 → 换图照常发生，两者不冲突

健壮性：

### 🅱 实现完工作模式后追加的申请（下面两条是用变通绕过去的，不是没做）

> 这两条都**没有动冻结层**，各自都有可用的降级路径；写在这里是因为
> 「用写操作读状态」「靠启发式猜数据丢了」都不该是长期方案。

**① `getSettings()` —— 读回当前设置（优先级：中）**

- **需要什么**：能把主进程里 `data.settings` 读出来（至少 `clipboardWatch`）。
- **为什么模式层自己实现不了**：`preload.js` 只暴露了 `setSettings(patch)`，
  没有对应的读接口；设置存在主进程里，渲染进程没有别的合法读法。
- **期望接口**：`window.naiwa.getSettings()` → `Promise<{clipboardWatch, cpuWatch, clipLimit}>`。
- **现在的变通**：面板调 `setSettings({})`——传空补丁时 `main.js` 的 handler
  会把合并后的设置原样返回，且不改任何值。能用，但**语义是脏的**（用写操作读状态），
  已经写在 `renderer/panels.js` 的注释里。
- **影响**：面板里「记录剪贴板历史」开关的初始状态。托盘菜单里关掉过的话，
  面板靠这个变通才能显示正确；读不到时会退回「默认开」并在 UI 上说明以托盘为准。

**② 数据加载状态 —— 让「数据可能丢了」有个准确来源（优先级：中）**

- **需要什么**：`main.js` 读 `naiwa-data.json` 失败（JSON 非法 / 读不动）时，
  把这个事实暴露给渲染进程。
- **为什么模式层自己实现不了**：`loadData()` 的 catch 是空的，**静默**回退默认值；
  渲染进程拿不到任何信号。而「便签和剪贴板历史突然全空」恰恰是最需要解释给用户的场景。
- **期望接口**：`window.naiwa.getDataStatus()` → `Promise<{ok, reason?: 'missing'|'corrupt'|'io', at}>`，
  或者在启动时推一条 `data:status`。
- **现在的变通**：面板用 `localStorage` 记「上一次有多少条记录」，这次读到 0 而上次大于 0
  就提示「数据可能已丢失」。只在**整体变空**时触发，而且用户自己删空时会同步更新标记，
  所以不会误报；但它分不清「文件损坏」「文件被删」「路径变了」，也说不出具体原因。

**③ 按状态区分命中区（优先级：低）**

- **需要什么**：允许素材槽位覆盖命中区（例如 `sweat: { kind:'file', src:…, hit:{…} }`），
  或者让核心层按当前基础层挑一组 `hit`。
- **为什么模式层自己实现不了**：`hit` 只有 `assets/manifest.js` 里那一组（共享文件），
  而不同姿势的轮廓宽度差很多：`idle_relax` 152px、`sweat` 196px、`idle_work` 262px
  （都是 380 画布坐标），一组固定椭圆只能贴合最窄的那张。
- **现在的代价**：换成 `idle_work` 后，两侧各有约 11 CSS px 看得见、点不到
  （点到的是桌面）。不影响主流程，但确实是手感问题。

*其余为空。*

| # | 申请 | 裁决 | 落地情况 |
| --- | --- | --- | --- |
| ① | `getSettings()` | ✅ **已批准并落地** | `window.naiwa.getSettings()` → `Promise<{clipboardWatch, cpuWatch, clipLimit}>`（返回副本）。面板可以直接用它做初始状态，**不再需要 `setSettings({})` 空补丁那个变通** |

**关于 ③ 的一个更正**：第 10 节写「两侧各有约 11 CSS px 看得见点不到」，
实测比这个大——按包围盒算是**每侧约 27.5 CSS px**（`idle_work` 宽 262，
命中椭圆换算到画布坐标只有 152，`(262−152)/2 = 55` 画布 px = 27.5 CSS px）。
所以这条从「低」提到了「中」。

**自己量槽位 `hit` 的方法：**

```bash
ffmpeg -i assets/work/sweat.png -vf "alphaextract,bbox" -f null -
# → x1:92 x2:287 y1:44 y2:348 w:196 h:305

# 素材是 380×380 时，换算成相对显示区（190×190）的比例：
#   rx = w / 2 / 380     ry = h / 2 / 380
#   x  = (x1+x2) / 2 / 380   y = (y1+y2) / 2 / 380
```

⚠️ `rx` / `ry` 别调得比主体明显大——那会让窗口在看不见的地方拦住桌面点击。
**宁可小一点**：点不中边缘只是手感差，挡住桌面用户会直接卸载。

**注意**：第 10 节里 ① 和 ② 描述的「现在的变通」（空补丁读设置、localStorage 猜数据）
**都已经过时**，接口到位后应该换掉。
