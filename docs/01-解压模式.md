| --- | --- | --- |

> 📌 **关于时长**（第四次会话，用户反馈「大笑只有一小段」之后定的）：
> 当时的实现是「取源片 1.55s 起的 0.95 秒做**乒乓**（正放+倒放）」= 26 帧 / 1.73 秒，
> 只占源片 6%，观感是嘴一张一合的小抖动。现在**整片 0→15.4s 正放到底**。
> 为什么当初要乒乓：想靠素材自己回到静息姿势，避免「笑完回待机」硬切。
> 现在不需要了 —— ①源片本来就有闭嘴恢复段；②交付版最后几帧又站回原姿势；
> ③表现层切换本来就有 0.12s 交叉淡入（`core/pet.js` 的 `switchTo`）。
>
> 时长由 `count / fps` 算出（`core/assets.js`），**改 count 就等于改时长**；
> 合成笑声（`core/audio.js`）会自己去清单里读同一个值来填满，不用手抄。
> 素材处理见 `.assetwork/README.md`，越界检查（奶蛙跳起/摔倒会不会被裁）在 `build.js` 里。

## 4. 行为规格

### 4.1 静态待机

进入模式后就是一张静态图，什么都不做。不要加呼吸、摇摆之类的循环动画——**这是明确的需求**。

只有视线跟随（`ctx.pet.lookAt`）可以保留，那是交互反馈，不算"待机动作"。

### 4.2 点击 → 大笑

```
用户左键点奶蛙
  → 播放大笑动画 + 大笑音效
  → 两者时长自动对齐（音效时长作为基准）
  → 播完回到静态待机
```

**要点：**

- **防连点冷却 240ms。** 低于这个间隔的点击直接丢弃。否则声音会叠成一片噪音，动画也会不停重头开始。
- **音效时长驱动动画时长。** `ctx.audio.play('laugh')` 会返回毫秒数，把它作为 `playOnce` 的 `duration`。这样"嘴巴"和"声音"是同步的。素材自带时长时以素材为准。
- **台词气泡**：连点到第 3、7、11… 次时随机冒一句（"哈哈哈哈！"、"好痒好痒～"、"再来再来！"）。别每次都冒，会烦。

### 4.3 连点 → 分身同步大笑 ⭐ 核心功能

**触发**：2600ms 内累计点击 **≥ 4 次**（从静态或大笑状态都可以触发）。

**表演分三个阶段，总时长约 1800ms：**

| 阶段 | 时长 | 内容 |
| --- | --- | --- |
| ① 分身出现 | ~140ms | 在主体左右各弹出一个分身，从中心散开 |
| ② 同步大笑 | ~1500ms | **主体 + 2 个分身在同一帧开始播放大笑动画** |
| ③ 分身消失 | ~160ms | 分身淡出并从 DOM 移除，主体回静态待机 |

**分身的视觉参数：**

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 数量 | 2（左右各一） | 需求指定 |
| 横向位置 | ±0.85 × 主体宽度 | 分开得够远才读得出是"两个分身"，又不至于出窗口 |
| 缩放 | 0.82 | 略小，避免和主体抢视觉焦点 |
| 不透明度 | 0.92 | 轻微透，暗示是"幻影"而不是三只真奶蛙 |
| 出现方式 | 从中心散开 + 淡入 | 比直接闪现更自然 |

**关键实现要求：**

1. **音效只播一次。** 三个实例同时出声会糊成一团，听起来像噪音而不是大笑。
2. **主体的大笑会重头开始。** 触发瞬间主体可能正在笑，此时三个一起从第 0 帧重启。这是**有意为之**——分身出现吸引了注意力，重启读起来像"笑得更起劲了"，不会觉得是故障。不要试图去对齐主体原来的进度，那做不干净。
3. **表演期间忽略点击。** 不要让它叠成 5 个、7 个分身。表演结束后清空连点计数并加 **3000ms 冷却**，否则残留的点击记录会立刻再次触发。
   > ⚠️ **冷却只拦分身，不能拦单次大笑。** 评审时发现早期实现把冷却检查放在了所有分支之前，导致表演结束后 3 秒内点奶蛙**完全没有反应**（没动画没音效），用户会以为程序卡死。正确写法是只让分身分支看冷却：
   > `if (n >= 阈值 && t >= cloneCooldownUntil) doCloneShow(); else doLaugh(n);`
4. **分身不可交互。** 加 `pointer-events: none`，且它们本来就在命中椭圆之外。
5. **`deactivate()` 里必须清场。** 用户可能在分身表演到一半时右键切模式，此时分身 DOM、淡出定时器、动画回调都要清干净。

**具体调用方式见 [`00-协作约定.md`](00-协作约定.md) 第 4.1 节的 `ctx.pet.performWithClones()`。**

### 4.4 久不操作 → 跑步 —— ⏸ **已取消**

> **这一节描述的规格仍然有效，但功能当前是关掉的**（`CONFIG.RUN_ENABLED = false`）。
> 保留它是为了将来拿到合适素材时能直接恢复，不用重新设计。

**触发**：静态状态 + 60 秒无任何交互。

`onIdleTick(ctx, idleMs)` 每 5 秒回调一次，所以在 `idleMs >= 60000` 时触发（实际会在 60~65 秒之间，可以接受）。

**效果：**

- 播放跑步循环动画（`ctx.pet.playLoop('run')`）
- 主体左右往返移动，幅度 **±80px**，单程 **3200ms**
- 移动范围很小是有意的：桌宠是背景陪伴，不是来抢注意力的

**结束条件（任一）：**

- 用户点击奶蛙 → 停止跑步，**平滑归位**，然后立即走一次正常的大笑流程
- 鼠标移入奶蛙身体范围（用 `ctx.pet.containsPoint(x, y)` 判断）→ 停止跑步，平滑归位
- 切模式 / `deactivate()`

**「平滑归位」是个真实的坑。** 直接停掉移动动画，奶蛙会瞬间跳回中心，看起来像闪了一下。正确做法见第 5.2 节。

### 4.5 右键：单击弹操作窗，双击切换模式

由核心层处理，你不用管。但要保证 `deactivate()` 能干净地中断上面任何一个进行中的表演。

> **第五次会话改过语义**：以前是「右键单击 = 切模式」，现在单击让位给**操作窗**
>（切换模式 / 打开面板 / 退出奶蛙），切模式改成**右键双击**。
> 判定在 `renderer/app.js` 的「右键操作窗」一节：单击立刻弹菜单，
> 若 400ms 内又来一次右键就把菜单收起并切模式（不做延迟等待，否则菜单每次都慢半拍）。
> 操作窗的项按模式显隐（「打开面板」只在工作模式出现），并且参与点击穿透判定
>（`isInteractiveAt` 认 `#pet-menu`），光标移开 / Esc / 点任一项都会收起。

## 5. 两个关键技术点

### 5.1 分身同步：为什么必须用序列帧

「同步大笑」听起来简单，但对素材格式有硬性要求。

**如果用 3 个 `<video>` 元素：** 每个视频独立解码，`currentTime = 0` 之后的实际起播时间会有几毫秒到几十毫秒的差异。三个视频各自跑各自的时钟，误差还会累积。结果就是**看起来不齐**——而"不齐"会让整个功能显得很廉价。

**如果用一个 `<img>` 加载动画 WebP/GIF：** 浏览器不保证同一张动图的多个 `<img>` 实例帧同步，而且根本没法让它"回到第 0 帧重播"。

**正确做法：PNG 序列帧 + 共享帧计数器。**

三个 canvas 由**同一个帧计数器**驱动，同一帧画第 N 张图，可以做到严格同帧。

```js
// 伪代码：核心层 performWithClones 内部应该是这个形状
await ctx.pet.preload(['laugh']);          // 素材已在内存，播放时不会触发加载

const layers = [mainLayer, cloneL, cloneR]; // 全部已挂载
let frame = 0;

requestAnimationFrame(function tick(now) {
  // 三个 layer 在同一帧画同一张图
  layers.forEach(l => l.drawFrame(frame));
  frame++;
  if (frame < totalFrames) requestAnimationFrame(tick);
  else finish();
});
```

**所以：把大笑素材做成序列帧。** 这一条决定功能能否成立。

如果你手上只有一段视频，用 ffmpeg 拆成序列帧：

```bash
ffmpeg -i laugh.webm -vf "scale=380:380" -start_number 1 laugh_%04d.png
```

### 5.2 跑步平滑归位

跑步位移用 **Web Animations API** 而不是 CSS animation，因为需要能暂停并读出当前位移：

```js
// 起跑
const petEl = /* 主体元素 */;
let runAnim = petEl.animate(
  [{ transform: 'translateX(-80px)' }, { transform: 'translateX(80px)' }],
  { duration: 3200, direction: 'alternate', iterations: Infinity, easing: 'ease-in-out' }
);

// 停下并平滑归位
function stopRun() {
  const m = new DOMMatrixReadOnly(getComputedStyle(petEl).transform);
  const cur = m.m41;                    // 当前 X 位移
  runAnim.cancel();

  petEl.style.transform = `translateX(${cur}px)`;
  const back = petEl.animate(
    [{ transform: `translateX(${cur}px)` }, { transform: 'translateX(0)' }],
    { duration: 250, easing: 'ease-out', fill: 'forwards' }
  );
  back.finished.then(() => { petEl.style.transform = ''; });
}
```

**位移必须加在 `#pet` 元素本身**，不要加在内层容器上。因为命中判定用的是 `#pet` 的 `getBoundingClientRect()`，而 `getBoundingClientRect()` 会包含元素自身的 transform——位移加在内层的话，奶蛙跑出去了，但"可点击区域"还留在原地，用户会发现点不到它。

## 6. 状态机

```
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   ┌─────────┐   点击（冷却 240ms 后）   ┌──────────┴───┐
   │ static  │ ───────────────────────→ │  laughing    │
   │ 静态待机 │                          │  一次性大笑   │
   └────┬────┘ ←─────────────────────── └──────────────┘
        │              播完自动回                     ▲
        │                                           │ 连点 ≥4
        │  连点 ≥4                                  │
        ├──────────────────→ ┌───────────┐ ─────────┘
        │                    │  cloning  │
        │                    │ 分身同步笑 │
        │                    └─────┬─────┘
        │                    播完 + 3s 冷却
        │                          │
        │                          ▼
        │                     （回 static）
        │
        │  空闲 ≥60s
        ▼
   ┌──────────┐   点击 / 鼠标移入 / 切模式
   │ running  │ ─────────────────────────────→ 平滑归位 → static
   │  跑步循环 │                                （点击的话归位后立即大笑）
   └──────────┘
```

**优先级**：`cloning` > `running` > `laughing` > `static`

任意状态收到 `deactivate()` → 立即清场回 `static`。

## 7. 可调参数

在 `renderer/modes/relax.js` 顶部放一个 `CONFIG` 对象，集中管理：

```js
const CONFIG = {
  // 点击大笑
  CLICK_COOLDOWN: 240,        // ms，两次触发的最小间隔
  LAUGH_FALLBACK_MS: 1500,    // 素材没写时长时的兜底

  // 连点分身
  CLONE_WINDOW: 2600,         // ms，连点统计窗口
  CLONE_THRESHOLD: 4,         // 触发分身的点击数
  CLONE_COOLDOWN: 3000,       // ms，表演后的冷却
  CLONE_COUNT: 2,
  CLONE_SPREAD: 0.85,         // 相对主体宽度的横向展开
  CLONE_SCALE: 0.82,
  CLONE_OPACITY: 0.92,
  CLONE_FADE_OUT: 160,        // ms

  // 跑步
  RUN_ENABLED: false,         // ⏸ 总开关：没有可用素材，功能停用（见 3.3）
  RUN_IDLE_MS: 60000,         // 空闲多久触发
  RUN_RANGE: 80,              // px，往返幅度
  RUN_CYCLE: 3200,            // ms，单程时长
  RUN_RETURN: 250,            // ms，归位过渡

  // 台词
  IDLE_TALK_ENABLED: false,   // ⏸ 总开关：闲置自动自言自语已取消（用户要求）
  IDLE_LINE_CHANCE: 0.06,     // 每次空闲心跳冒台词的概率
  IDLE_LINE_MIN_MS: 45000,    // 至少闲置这么久才开始自言自语
  MOOD_LINES: ['在忙什么呀？', '陪我玩会儿嘛', '咕噜咕噜…', '今天也要加油哦'],
};
```

> 两个 `*_ENABLED: false` 都是**总开关**：代码原样保留（项目没有版本控制），
> 改回 `true` 就恢复。冒烟测试会读这两个开关：关着时相关验收项 SKIP 并说明原因，
> 打开时自动恢复成真断言（见 `docs/04` 第 8.7 节）。
>
> 「闲置说话」关掉的是**自己冒台词**；点它时的 `LAUGH_LINES`、切模式时的问候都不受影响。

**这些值都是拍脑袋定的起点，不是真理。** 做成真实素材后要实际看效果调整——尤其 `CLONE_THRESHOLD`（点几下才出分身）和 `RUN_IDLE_MS`（多久才跑起来），这两个直接决定手感。

## 8. 验收清单

功能层面：

- [ ] 进入模式后奶蛙是**静止**的，没有任何循环动画
- [ ] 点一下 → 大笑 + 音效，笑完回静态
- [ ] 快速点 4 下（2.6 秒内）→ 出现 2 个分身，**三个严格同步大笑**，笑完分身消失
- [ ] 分身表演期间继续点击**不会**产生更多分身
- [ ] 分身表演结束后 3 秒内不会再次触发
- [x] ~~闲置约 60 秒 → 开始跑步，左右往返~~ —— ⏸ **功能已取消**，当前不该观察到跑步
- [ ] 闲置 60 秒后奶蛙**保持静止**（只可能冒台词，不会移动）
- [ ] 鼠标在窗口内移动时，奶蛙的瞳孔会跟随（占位素材）

健壮性（这些最容易漏）：

- [ ] **分身表演到一半右键切模式** → 分身立刻消失，不留残影
- [x] ~~跑步到一半切模式 → 位移归零~~ —— ⏸ 随功能取消，恢复后需重新验证
- [ ] 来回切模式 20 次 → 行为不叠加（比如两个大笑定时器同时在跑）
- [ ] **删掉 `assets/relax/` 下所有素材** → 程序照常启动，退回占位奶蛙，交互全部可用
- [ ] 只提供静态待机图 → 点击不会崩（没有大笑素材时应退回占位大笑或安静地什么都不做）
- [ ] 疯狂连点 30 秒 → 不出错、不爆内存、分身不累积

## 9. 不要做的事

| 别做 | 为什么 |
| --- | --- |
| ❌ 给待机加呼吸/摇摆动画 | 需求明确说待机不做动作 |
| ❌ 改 `pet.js` 去实现分身 | 那是冻结层，走申请流程 |
| ❌ 让分身在窗口里乱跑或多个分身 | 需求是 2 个，多了就是噪音 |
| ❌ 跑步时来回幅度搞很大（>150px） | 桌宠会变成干扰源，用户会关掉它 |
| ❌ 跑步时循环播放脚步声 | 长时间的环境音非常烦人 |
| ❌ 直接改 `core/style.css` | 写进 `modes/relax.css` |
| ❌ 用视频做大笑动画 | 分身同步会不齐，见 5.1 |
| ❌ **跳过阶段 1 直接写功能** | 结构债会让接手的人在你的代码里挣扎，最后两边缠成一团 |
| ❌ **阶段 2 开始后还去改共享层** | 那时它是你和接手者共同的基线，改了要写进交接文档 |

### 关于「改动共享层」的分寸

阶段 1 你要动 `core/**`、`app.js`、`pet.js`，这没问题。但进入阶段 2 之后：

- 发现 `ctx` 少了个能力 → 可以加，但**必须写进 `docs/交接-A到B.md`**
- 改了任何冻结层文件 → **同上**
- 只是觉得某段代码写得不好 → **别动**。它已经在工作了，重写只会引入风险

判断标准很简单：**接手的人只会读 `00-协作约定.md` 和你的交接文档。任何没写下来的改动，对他来说就是"和文档不一致"。**
