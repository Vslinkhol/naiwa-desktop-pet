## 4. 实现里几个不显然的决定

**① CPU 用滞回状态机，并且每拍「自愈」。**

```
hot = hot ? percent > 62 : percent >= 75      // 中间 13 个点维持原状态
```

单阈值不行：负载在 75 附近抖动时奶蛙会疯狂来回切图，看起来像 bug。
另外还有一条不显然的：**有些路径会把基础图顶掉**——拖拽（`drag` 姿势）、
勾选待办时的大笑，它们结束时表现层回的是「静态待机」而不是 `sweat`。
所以热态下每收到一次 CPU 推送就重新确认一次 `playLoop('sweat')`
（幂等：已经挂着时等于空操作），反应进行中则跳过、等反应结束再挂回去。

**② `has()` 一定 await，而且是「素材没就位就什么都不挂」。**

`ctx.pet.has()` 是异步的，它确认的是「素材真的挂载成功」。
为假时**不调** `playLoop('sweat')`——那会挂上画风差很远的占位卡通蛙。
退化成「只播 drip 音效 + 冒一句台词」，画面保持静止待机。

**③ 面板 → 模式层是一条显式的事件通道，不是靠猜。**

「勾选完成让奶蛙笑一下」这件事，面板得通知模式层。但 `app.js` 传进
`Naiwa.Panels.init()` 的钩子集合是固定的（而且 `app.js` 冻结），所以
`panels.js` 导出 `Naiwa.Panels.on(event, cb)`（返回退订函数），
`work.js` 在 `activate` 订阅、`deactivate` 退订。音效仍然走核心层的钩子，
两边不打架。

**④ 面板里的隐私开关要读设置，而 `preload.js` 只有 `setSettings`。**

现在的做法是 `setSettings({})`——传空补丁时主进程把合并后的设置原样返回，
且不改任何值。能用，但**语义是脏的**（用写操作读状态），已经写进
`docs/02-工作模式.md` §10 申请 `getSettings()`。读不到时会退回「默认开」，
并在 UI 上说明「以托盘菜单为准」，不假装知道。

**⑤ 数据丢失的提示是启发式的。**

`main.js` 读坏了 JSON 会**静默**回退空数组（那本身是对的，不能因为数据坏了就起不来），
渲染进程拿不到任何信号。所以面板在 `localStorage` 里记「上一次有多少条记录」，
这次读到 0 而上次大于 0 就提示「数据可能已丢失」。
只在**整体变空**时触发，而且用户自己删空会同步更新标记，所以不会误报；
但它分不清「文件损坏 / 被删 / 路径变了」。精确方案需要主进程暴露加载状态，
同样写在 §10。

**⑥ 长列表分片渲染，不是一次性堆 DOM。**

便签和剪贴板都先渲染 60 条，滚到底部再续一屏（`PAGE = 60`）。
重绘时会保存/恢复 `scrollTop`，免得数据一变就把用户弹回顶部。
搜索/排序/相对时间/内容大小这些照常。超长条目只渲染前 4000 字符
（完整内容点一下照样原样复制，只是不进 DOM）。

**⑦ `hidden` 属性对 `.panel` / `.pane` 是失效的（这条是「不修就整个功能不成立」）。**

浏览器默认样式表里的 `[hidden] { display: none }` 是 **UA 样式**，
而作者样式 `.panel { display: flex }` / `.pane { display: flex }` 永远压过它。
也就是说：面板从来就没被隐藏过——它一直显示着，两个标签页还会同时出现；
更糟的是 `app.js` 的点击穿透判定用 `elementFromPoint` 找 `#panel`，
面板一直「显示」就意味着窗口在看不见的地方拦截鼠标，用户点不到桌面图标。

修法在 `modes/work.css`（我自己的文件）：
`#panel[hidden] { display: none }` + `#panel [hidden] { display: none }`。
冒烟测试里 W3 专门盯这一条（收起后 computed `display` 必须是 `none`）。

## 6. 发现的问题（**不在我的文件里，我没有动**）

### 6.1 `renderer/modes/relax.js` 里有一个「同步调异步 `has()`」的漏网调用点

```js
// renderer/modes/relax.js  activate()
const warm = ['laugh'];
if (ctx.pet.has('run')) warm.push('run');   // ← 漏了 await
await ctx.pet.preload(warm);
```

`has()` 在独立评审后从同步改成了异步（见交接文档 §11.1-4），
`startRun()` 里的调用点改对了，`activate()` 里这个没改。
异步函数返回的 Promise **恒为真**，于是 `warm` 永远包含 `'run'`，
`preload(['laugh','run'])` 会为 `run` 挂上一个**占位卡通蛙**（`kind:'none'` 的槽位）
到基础层里（透明度 0，看不见）。

后果有两个，都不致命但都会误导人：

1. `#pet` 里常年存在一个 `.ph-frog` 占位节点；
2. 解压模式冒烟测试的 **S12（瞳孔跟随）从 SKIP 变成 FAIL**——它先找
   `#pet .ph-pupils`，找到了（那是 `run` 占位蛙的瞳孔，且藏在透明度 0 的层里），
   于是不再走「真实素材没有瞳孔 → SKIP」的分支，改判「瞳孔没跟随 → FAIL」。

**一行修复**：`if (await ctx.pet.has('run')) warm.push('run');`

**我没改**——文件边界写着 `modes/relax.*` 不许动，而且解压模式已经验收过了。
这一条也是我开工基线里那个 FAIL 的全部原因：`__smoke.js` 在开工前后都是
「17 PASS / 1 FAIL(S12)」，FAIL 是我接手前就有的。

### 6.2 交接文档的一处更正

`交接-A到B.md` §6.1/§10 说 `.assetwork/`（素材处理脚本目录）**不存在**。
实际是存在的，只是在**工作区根目录**（`<工作区>/.assetwork/`），不在项目里，
所以从项目里看不到。里面就是 🅰 的解压模式素材脚本（`assetlib.js` / `build.js` 等），
我复用同一套库处理了工作模式的两张素材，脚本说明写在
`.assetwork/README-work.md`。

### 6.3 本机环境的一个限制（记录一下，免得下次再踩）

在 `naiwa-pet/assets/**` 里做 **rename / unlink** 会被系统拒绝（`EPERM`），
即使进程本身已经不受沙箱限制；`assets/` 之外的目录（项目根、工作区根、
`.assetwork/`）都正常。**普通写入是允许的**（素材构建脚本就是直接写进 `assets/`
完成的）。所以任何「先移走再移回」的测试思路在这里都不成立，
要用「写坏 + 按内存恢复」或者「改清单指向」。
